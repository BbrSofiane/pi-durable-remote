# Implemented terminal presentation

This is a thin local terminal face, not a web client or a local coding-agent runtime. It uses released `@earendil-works/pi-tui` **1.2.0**; all other direct Earendil packages remain pinned to **1.1.0**. Node >=22.19.0 remains required.

## Hierarchy and paired surfaces

- User messages occupy a small native `Box` surface. Assistant prose stays on the terminal-owned canvas with native `Markdown`, explicit Thinking labels and a blank row between turns. Tool-only assistant turns do not add a redundant Assistant label.
- Each tool execution has one bounded native `Box`: status/duration, meaningful primary intent, committed output, and expandable original arguments/details/diagnostics. Bash shows the sanitized literal `$ command`, not its JSON encoding. Read/write/edit show the remote path; unknown tools use their name plus accessible original arguments. No local path lookup or diff calculation occurs.
- Pairing is scoped to the committed assistant occurrence, with keys derived from entry ID/message/block occurrence, never a global call-ID map. Parallel results can arrive in either order. Reused IDs cannot reach across a later round. A live slot's explicit result entry is preferred; otherwise only the current round is eligible. Results replace live progress, not duplicate it. Unmatched results/slots and unavailable results remain visible. Text states distinguish pending, running, done (success), error, not-run and interrupted. Duration is displayed only when committed `durationMs` is supplied.
- `theme.ts` is the single color seam and mirrors the released Pi dark/light palettes (published `dark.json`/`light.json` tokens, read-only reference): violet accent, green success, yellow warning, warm red error, blue-tinted user surface (`blueBg`), green success-tool surface, neutral pending and red error-tool surfaces. Truecolor terminals get those real okhsl hues; the deterministic 256-color fallback quantizes to fixed standard cube/grayscale indices (never terminal-custom 0–15) with three measured overrides (dark user background/output, light output) so every owned pair stays ≥4.5:1 and all four surfaces stay distinct. The color mode comes from the public pi-tui capability detection, not assumptions. Canvas and assistant body foreground stay inherited; no full-canvas paint. Small surfaces always pair their own foreground/background: explicit text on each semantic surface, tool output/expansion hints subordinate but ≥4.5:1 on their owned background, verified numerically against emitted RGB and the 256 fallback. Status words and spacing, not color alone, carry meaning.
- Appearance is a presentation-only guess: explicit `PI_UI_APPEARANCE=light|dark` wins, then a conservative `COLORFGBG` background hint (7/15 → light), else dark. No automatic light detection is claimed; no terminal OSC queries, theme watchers or app-wide theme framework. `NO_COLOR` removes all presentation styling, including surfaces and bold/italic; explicit labels, spacing, omitted counts and controls remain. Footer metadata/work counts render in the muted color, while recovery and error text stays at full readable status styling. Native Markdown uses restrained Pi semantic roles (yellow headings, blue links, violet code, green code blocks); no URL activation callback is installed.
- The editor retains native pi-tui editing/history and the hardware cursor. pi-tui 1.2 resolves its internal zero-width APC cursor markers before terminal writes; the client does not interpret or forward them itself.

## Bounded previews and controls

Tools start collapsed. A small preview adapter measures native `Text.render(width)` rows: at most two primary-command rows and five output rows, followed by the exact omitted rendered-row count and `Ctrl+O` hint. Wide Unicode/emoji/combining text is bounded by terminal columns, not newline count. Original arguments and committed details/diagnostics are included in the omitted count. **Ctrl+O** expands all tools to show every retained argument/output/detail/diagnostic and toggles back to compact previews. The preference lives only in the transcript component, surviving fresh whole snapshots, finishing tools and reconnects. It never modifies committed/frozen payloads or sends a network frame. Remotely dropped output cannot be reconstructed; its committed truncation diagnostics remain accessible. `transcriptText` stays full and source-like, including details/diagnostics.

The native vertical composition is scrollable transcript, persistent recovery panel, notices, editor, two-row connection/work/model/remote-path footer and compact primary controls. Remote paths are abbreviated purely as strings, with a visible basename; no git/filesystem query occurs. Routine “Connected; fresh whole snapshot received” notices are filtered from the visible notice area, not errors or uncertainty. The footer shows Enter/follow-up, exit and expansion; recovery actions appear in their dedicated panel when needed.

Full controls: Enter submits a follow-up; Shift+Enter inserts a newline; Ctrl+A aborts; Ctrl+R resyncs; Ctrl+C exits without abort; PageUp/PageDown scroll; Ctrl+Shift+F opens native transcript search. Exact argument-less `/recover` and `/discard` act on the oldest retained in-memory receipt. Recovery requires a fresh connected snapshot of the original persisted session, reuses the same immutable request ID/payload and never runs automatically. Discard is local only. Closing the client loses receipts, not remote work.

At 36×20, all seven recovery rows remain protected: count, eligibility, original-input/ID preview, same-ID/retyping warning and local-only discard instructions. Transcript/notices/editor yield space first. Other chrome may clip in constrained viewports; no claim is made that every long error or metadata character fits simultaneously. Draft, cursor, focus and manually selected history position are not reset by expansion or snapshot updates.

## Data boundary

Remote controls are stripped before trusted Markdown/style callbacks. In expanded JSON, original control bytes appear only as inert escaped literals. No repository, credentials or files are read for completion, highlighting or edit previews. No local-file autocomplete, URL opener, custom terminal/layout/editor engine, animation, protocol change, incremental network reducer or disk outbox is introduced. The screenshot's separate server runtime-context issue is implemented server-side: the server supplies this context (configured model, workspace, durable store and diagnostics guidance) from its startup configuration. This adds no client filesystem access and no repository-instruction loading, and no claim is made that the deployed VM has been upgraded.

## Reproducible frame evidence

From the repository root, using installed dependencies and faux/in-memory providers only:

```sh
PI_UI_FRAME_DIR=/tmp/pi-durable-toolblocks-frames node --experimental-strip-types --test packages/client/test/toolblocks.test.ts packages/client/test/presentation.test.ts packages/integration/test/terminal.test.ts
npm run check && npm test
node --test scripts/test/*.test.mjs
```

The first command captures actual current `TuiAltScreen.getScreenLines()` ANSI/plain frame pairs at 36×20, 80×20 and 100×20 — dark truecolor, light appearance and `NO_COLOR`, collapsed and expanded tools, running/error tools, user/Markdown/code landmarks and complete ready/stale recovery panels. Toolblocks frames use real `runRemoteTui`/Editor/Harness/SQLite and real local Ctrl+O, including Unicode shell output, collapsed/expanded tools and retained drafts. Default captures exercise the public pi-tui color-mode detection (256-color here); the dedicated theme test additionally asserts emitted truecolor/256 pairing, published-token equality, deterministic cube/grayscale indices ≥16 and numeric ≥4.5:1 foreground/background contrast on every owned surface in both modes and appearances. PTY JSON captures actual CLI writes/termios restoration, expansion, and same-ID recovery across a server restart. The tests separately exercise reused IDs, parallel/out-of-order results, orphan/missing results, frozen payloads, full diagnostics and paired foreground/background styles. Earlier “before” frames reconstruct the pre-redesign composition; the user's Pi-left/app-right screenshot is the visual reference for this pass, not those synthetic before frames.

ANSI/plain captures are the accepted evidence for this slice. No browser/PNG capture, physical-terminal palette measurement or human visual approval is claimed. Automated pairing assertions cover light/dark canvas independence; real terminal palettes can still vary.
